## What's new in 0.10.2

### NachoCombo MCP: every gadget, one set of tools
- Every gadget now has tools that Nacho and outside MCP clients can use: Window Snap, Menu Bar Organizer, System
  Monitor, Disk Map, Clipboard History, File Shelf, Capture Float, Focus Dim, Keep Awake, Device Control, Mouse Tune,
  App Switch, Calendar Clock and Computer Use. Both sides use the same tools.
- Each gadget comes with a short guide: what it can do, the order of calls, examples and limits. MCP clients read it
  as `nachocombo://gadgets/<id>/guide` and get prompts for common flows. Nacho reads it with `combo_gadget_guide`.
- Windows can go anywhere: any number of rows and columns (for example 10×2), every open window on every screen,
  halves, thirds and quarters, your own ratios, across displays. Nacho can also place each window by hand (diamond,
  circle, steps…). A window that refuses a size is placed as close as it allows, and the answer says what changed.
  **Undo** puts the last arrangement back in one step.
- Nacho can read gadget data: CPU, memory, network and battery, the largest folders from the last Disk Map scan, the
  clipboard list (kind and length only), the shelf list, menu bar items, open windows.
- Computer Use for Nacho: screenshots, reading what is on screen (the Accessibility tree), clicking, typing, shortcuts
  and scrolling. AppleScript, shell, file access and force quit stay closed to Nacho.

### Nacho asks before content leaves this Mac
- Clipboard text, a screenshot or capture, a shelf file, and every click or keystroke from Computer Use show an
  approval card **every time**. Lists (numbers, kinds, lengths, names) never ask.
- Each of these gadgets has an **always allow** switch. It is off by default and you can switch it off at any
  time; while it is switching off, Nacho is asked again rather than let through.
- Things that cannot be undone, such as quitting an app or **emptying the File Shelf**, always ask, even with always
  allow on. Emptying the shelf used to run without a card.

### Computer Use is one switch; MCP has its own page
- The Computer Use gadget is now a single switch with an emergency stop. Switching it on asks macOS only for the
  permissions that are missing (Accessibility, Screen Recording). A missing one shows one line with **Open
  Settings**, and the line goes away when you come back after allowing it. Resetting the Accessibility permission is
  under **Troubleshooting**.
- The new **Settings ▸ MCP** page holds what used to be on that card: the server switch, address and port, LAN mode
  and its certificate, **API Keys**, tool groups, **Gadget Tools** (which gadgets outside clients may use, all off by
  default), recent calls and a client example. Nothing was removed.
- The two switches are independent. Turning the MCP server off keeps Nacho's Computer Use working and closes the
  port. If Computer Use was on before this update, the MCP server stays on, so connected clients keep working. Your
  port, LAN mode, groups and keys are kept.
- Outside MCP clients get no approval card. Their only gates are the API key and the switches, the same way as the
  high-risk tool groups before.

### Desktop tidy-up, with a preview and undo
- Ask Nacho to tidy the Desktop. It first shows a plan that sorts loose files into screenshots, images, documents,
  archives, installers and other, into a `정리됨` folder on the Desktop. Nothing moves until you approve it.
- Files are only moved, never deleted or overwritten. One step undoes the last tidy-up, and the last 30 days of
  tidy-ups are kept. Folders, apps, aliases, hidden files, downloads in progress and files changed in the last two
  minutes are left alone.
- Nacho can also suggest a window arrangement and apply it after you say yes.

### Staying signed in to Nacho
- If you deny or close the Keychain prompt, Nacho no longer signs you out. The tile says **Keychain access denied ·
  click Nacho to retry**, and allowing it on the next try restores your sign-in without the login page.
- Nacho's secrets are now kept in one Keychain item, so a new build asks at most once instead of once per item.
  Older items are moved over without deleting anything.
- The app is still ad-hoc signed, so macOS may ask for the Keychain password once after this update.

Your settings stay as they were.

**Not yet tried on a real Mac.** Everything above was checked with tests and off-screen renders in CI only.
Window and menu bar pictures in the review were drawn from the computed layout, not taken from a real screen.
Nacho's chats were tested with fixed data, not the live server. Not checked on a Mac: the order of permission
prompts, moving real windows and minimum sizes, folding the menu bar, LAN and TLS connections, the Desktop folder
permission, the Keychain prompt, and settings being carried over by the update.
