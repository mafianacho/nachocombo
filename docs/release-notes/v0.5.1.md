## What's new in 0.5.1

- **Automatic updates.** Nacho Combo now downloads a new version in the background, checks it (the release's
  `SHA256SUMS.txt`, bundle id, version and code signature) and installs it **when you quit** (also at logout or
  restart); if that did not happen, the next launch installs it first. It never restarts by itself while you use it.
  **Restart to Update** in the menu bar menu installs at once. General ▸ Updates ▸ **Install Automatically** (on by
  default) turns this off; then nothing is installed until you click Update…. New versions are looked for at launch and
  every 6 hours.
- **Few files.** At most two copies are kept on your Mac: the version waiting to be installed and the one before the
  running version. Older copies, zips and interrupted downloads are deleted at once.
- **Go back any time.** General ▸ Updates ▸ **Revert to x.y.z…** puts the previous version back; automatic updates do
  not install the version you left again (a newer one still comes). Every version stays on the
  [Releases page](https://github.com/mafianacho/nachocombo/releases).
- **Automatic recovery.** If a new version fails to start properly twice in a row, the next launch goes back to the
  previous version by itself.
- **Computer Use: Accessibility no longer stays "Not allowed".** Up to 0.5.0 every build had its own code signature
  requirement, so after an update (or with another copy) the Accessibility switch in System Settings stayed on but no
  longer matched the running app, and Computer Use kept saying Needs Permission. From 0.5.1 the app is signed with a
  requirement on its bundle id, so a permission allowed once keeps working after later updates.
- **Computer Use opens with what is allowed.** A missing permission now only switches off the tool groups that need it
  (for example Input and Apps & Windows without Accessibility); the server opens with the rest (for example Screen).
  Once you allow the permission, the server opens or the waiting groups join within a few seconds, without clicking
  anything.
- **Permission diagnostics.** While a permission is missing, the Computer Use page shows where this copy runs from
  (with a warning when macOS runs it from a temporary App Translocation folder or the disk image), its bundle id and
  version, what macOS answers for Accessibility and Screen Recording, and **Reset Accessibility Permission…**, which
  clears Nacho Combo's entry and asks again.
- **Permissions after an update.** **Coming from 0.5.0 or older, allow Accessibility (and Screen Recording) once more
  after installing 0.5.1**: the stored permission belongs to the old signature. After that they stay allowed across
  updates. The first launch after an update lists the gadgets that lost their permission and opens the Permissions
  page.

**Coming from 0.5.0:** 0.5.0 has the old updater, so install this version **once by clicking Update…** (General ▸
Updates or the menu bar menu). From 0.5.1 on, updates are automatic.

**Security note.** The signature requirement names only the bundle id (the app has no paid Apple Developer ID), so
another app that a program already running on your Mac signs with the same bundle id would also match the stored
permission. See docs/COMPUTER-USE-MCP.md.

**Not yet tried on a real Mac.** The update engine was tested end to end against mock releases, on macOS in CI with real
`ditto` and `codesign`, but this version has not been run on a Mac. Limit: the automatic recovery runs inside the new
version, so a version that crashes before any of its code runs cannot go back by itself; download an older version from
the Releases page then.
